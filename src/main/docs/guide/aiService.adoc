=== Retrieval Augmented Generation

Retrieval is opt-in. An `@AiService` performs retrieval augmented generation (RAG) only when the application declares one of:

- a `dev.langchain4j.rag.RetrievalAugmentor` bean, or
- a `dev.langchain4j.rag.content.retriever.ContentRetriever` bean, which LangChain4j wraps in a `DefaultRetrievalAugmentor`.

A `RetrievalAugmentor` bean takes precedence over a `ContentRetriever` bean. For either type, a bean `@Named` after the service (for example `@Named("expert")` for `@AiService("expert")`) is preferred over the default bean. If several candidates exist and none is named after the service or marked `@Primary`, no retrieval is configured.

.Defining an `@AiService` that returns `Result<String>`
snippet::example.micronaut.aiservice.rag.Expert[source="main"]

<1> A plain `@AiService`; nothing on the interface refers to retrieval.
<2> Returning `dev.langchain4j.service.Result` exposes the retrieved sources alongside the answer.

.Declaring a `ContentRetriever` bean
snippet::example.micronaut.aiservice.rag.RetrievalFactory[source="main"]

<1> The bean is picked up by every `@AiService` that has no bean named after it. Add `@Named` to target one service.
<2> Build the retriever from the configured `EmbeddingStore` and `EmbeddingModel`.

.Retrieved content reaches the model and the result
snippet::example.micronaut.aiservice.rag.RagTest[source="test"]

<1> Ingest a segment into the embedding store.
<2> Call the service as usual.
<3> The retrieved segment is available as a source of the result.

To configure a single service, declare an api:langchain4j.aiservices.AiServiceCustomizer[] bean for it and call `contentRetriever(...)` or `retrievalAugmentor(...)` on `AiServiceCreationContext.aiServices()`, see <<aiServiceCustomization, Customizing AI Services>>.

NOTE: Before 2.3.0 an `EmbeddingStoreContentRetriever` was attached to every `@AiService` automatically whenever an `EmbeddingModel` bean and an `EmbeddingStore` bean existed. Because provider modules expose an embedding model and the in-memory embedding store is enabled by default, that was the case in most applications, causing an embedding round trip on every call and failures against models without embedding support. Declare a `ContentRetriever` bean as shown above to restore the previous behaviour.

[[configuringRetrieval]]
==== Configuring Retrieval

Content retrievers and the ingestion of documents can also be configured, without code.

A content retriever configured under `langchain4j.rag.content-retrievers.<name>` is an `EmbeddingStoreContentRetriever` bean qualified with `<name>`, so the `@AiService` with that name uses it:

.Example Configuration
[configuration]
----
langchain4j:
  rag:
    content-retrievers:
      expert:
        max-results: 3
        min-score: 0.6
----

include::{includedir}configurationProperties/io.micronaut.langchain4j.rag.ContentRetrieverConfiguration.adoc[]

An ingestion configured under `langchain4j.rag.ingestion.<name>` loads the documents of its sources when the application starts, splits them into segments, embeds them and adds them to the embedding store. The sources are directories of the file system, or of the classpath with the `classpath:` prefix. The documents are parsed with the `DocumentParser` that LangChain4j finds on the classpath (for example `dev.langchain4j:langchain4j-document-parser-apache-tika` for PDF and Office documents), and as text otherwise.

.Example Configuration
[configuration]
----
langchain4j:
  rag:
    ingestion:
      expert:
        sources:
          - classpath:docs
          - /var/data/manuals
        glob: '**.md'
        max-segment-size: 800
        max-overlap-size: 80
----

include::{includedir}configurationProperties/io.micronaut.langchain4j.rag.IngestionConfiguration.adoc[]

Both use the default `EmbeddingStore` and `EmbeddingModel` beans unless `embedding-store` and `embedding-model` name other beans. Each ingestion also creates an `EmbeddingStoreIngestor` bean qualified with its name, to ingest other documents programmatically. Set `ingest-on-startup` to `false` to only create the ingestor.

NOTE: The in-memory embedding store keeps the segments in memory only, so the documents are ingested again on every start. With a persistent embedding store, disable `ingest-on-startup` once the documents have been ingested, or ingest them with the `EmbeddingStoreIngestor` bean when they change.

A retrieval augmentor configured under `langchain4j.rag.retrieval-augmentors.<name>` retrieves content from one or more content retrievers and re-ranks it with a <<scoringModels, scoring model>>, so that only the most relevant content reaches the model. It is a `RetrievalAugmentor` bean qualified with `<name>`, which takes precedence over a content retriever with the same name:

.Example Configuration
[configuration]
----
langchain4j:
  cohere:
    api-key: ${COHERE_API_KEY}
    scoring-model:
      model-name: rerank-v3.5
  rag:
    content-retrievers:
      expert:
        max-results: 10
    retrieval-augmentors:
      expert:
        re-rank: true
        min-score: 0.7
        max-results: 3
----

The content retriever retrieves 10 segments by embedding similarity, and the scoring model passes the 3 most relevant ones with a score of at least 0.7 to the model.

=== Multimodal Parameters

An AI service can send images, PDF files, audio and video to the models that support them, together with the user message. Annotate a `String`, `URI` or `URL` parameter, or a collection of them, with ann:langchain4j.annotation.ImageUrl[], ann:langchain4j.annotation.PdfUrl[], ann:langchain4j.annotation.AudioUrl[] or ann:langchain4j.annotation.VideoUrl[]: the argument is sent as the LangChain4j content of that type.

snippet::example.micronaut.aiservice.multimodal.PictureDescriber[source=main]

<1> The picture at the URL is sent after the text of the user message. Like any content parameter of a LangChain4j AI service, the parameter is also annotated with `@UserMessage`.
<2> The content parameter can be combined with a user message template.

Parameters of the LangChain4j content types (`ImageContent`, `PdfFileContent`, `AudioContent`, `VideoContent`, or a `List` of `Content`) annotated with `@UserMessage` are also supported, for example to send an image read from a file.
