== Agentic Service

Micronaut lets you declare LangChain4j Agentic services and have concrete agents generated at runtime.

Add the following dependency:

dependency:micronaut-langchain4j-agentic[groupId=io.micronaut.langchain4j]

Annotate an interface with api:io.micronaut.langchain4j.agentic.annotation.AgenticService[] and declare methods using LangChain4j Agentic annotations.

[.lang-python]
NOTE: In Python an agentic service is an abstract class (`abc.ABC`) whose methods are declared with `...` bodies; the decorators mirror the LangChain4j annotations.

[.lang-python]
NOTE: LangChain4j builds the agents reflectively from the Java interface generated for the Python class and reads the `@Agent`, `@UserMessage`, `@SequenceAgent`, ... annotations from it. `@AgenticService` and the LangChain4j annotations imply the `@AllowsReflection` hint, so the Python compiler copies them onto the generated interfaces, including those of sub-agents and workflows declared without `@AgenticService`: no `@AllowsReflection` or `micronaut.introspection.allow-reflection` option is needed. The hint for the LangChain4j annotations is added by `micronaut-langchain4j-processor`, which must be on the compile classpath.

The integration interprets your annotations and uses Micronaut DI to wire the underlying LangChain4j builders.
It supports:

- Typed agents built via `AgenticServices.agentBuilder(Class)` with `@Agent` methods.
- Declarative workflow agents via `AgenticServices.createAgenticSystem(...)`.
- Micronaut model, memory, RAG, tool, and lifecycle integration for each generated agent builder.

=== Declarative workflows

You can build workflows using LangChain4j's declarative annotations. The integration routes construction through Micronaut DI so that supported workflow builders are Micronaut-managed beans (allowing listeners and customization).

=== Configuration

You can select which `ChatModel` bean to use per agent via configuration. The agent id is derived from the interface name by:

- stripping a trailing "Agent" suffix
- converting UpperCamel to lower-kebab (e.g. CreativeWriterAgent -> creative-writer)

[source]
----
langchain4j.agentic.agents.<agent-id>.chat-model
----

Examples

[configuration]
----
langchain4j:
  agentic:
    agents:
      greeter:
        chat-model: friendly-chat-model
      creative-writer:
        chat-model: creative-chat-model
----

If the property is not set and there is exactly one ChatModel bean in the context, it will be used automatically.

==== Memory

By default, agentic services reuse the core `MessageWindowChatMemory` built from the configured `ChatMemoryStore`. The core module publishes a `MessageWindowChatMemory.Builder` per available `ChatMemoryStore` (via `@EachBean(ChatMemoryStore)`), so agents automatically use the default builder when a single memory store is configured.

You can optionally override memory per agent:

[source]
----
langchain4j.agentic.agents.<agent-id>.memory.store

langchain4j.agentic.agents.<agent-id>.memory.max-messages
----

Notes:
- If `memory.store` is not set, the default `MessageWindowChatMemory.Builder` is used (as resolved by Micronaut DI).
- If multiple memory stores are available, set `memory.store` to select the store for an agent.
- If `memory.max-messages` is not set, the global core setting `langchain4j.chat-memory-store.message-window.max-messages` applies.

Examples

[configuration]
----
langchain4j:
  agentic:
    agents:
      greeter:
        memory:
          store: redis
      creative-writer:
        memory:
          max-messages: 50
----


==== Retrieval

Retrieval is opt-in. An agent performs retrieval augmented generation only when the application declares a `dev.langchain4j.rag.RetrievalAugmentor` bean or a `dev.langchain4j.rag.content.retriever.ContentRetriever` bean. A `RetrievalAugmentor` takes precedence over a `ContentRetriever`. For either type, a bean `@Named` after the agent id (for example `@Named("greeter")` for `GreeterAgent`) is preferred over the default bean. Embedding model and embedding store beans are never paired automatically.

=== Tools

You can request specific tool beans to be registered with the agent builder using the `tools` attribute.
Tool classes should be Micronaut beans containing methods annotated with `dev.langchain4j.agent.tool.Tool`.

=== Customization

You can customize builders using Micronaut lifecycle listeners. Because workflow builders are created as Micronaut beans during declarative system construction, your listeners can adjust names, exit conditions, parallelism, etc., before the system executes.

Typed agents can also be customized via `BeanCreatedEventListener<AgentBuilder<?, ?>>`; the `LoopingPlannerAgent` snippet above shows the same Micronaut lifecycle technique applied to `LoopAgentService`.

For example, this listener customizes every generated declarative agent builder before LangChain4j builds the agentic system:

=== Supervisor agents

A supervisor agent lets the chat model decide which of its sub-agents to invoke, and with which arguments, until the request is addressed. Declare it with LangChain4j's `@SupervisorAgent` on a method of an `@AgenticService`:

snippet::example.micronaut.agentic.TravelSupervisorAgent[source=main]

The supervisor plans with the chat model of the agentic service (see <<agenticServiceConfiguration, Configuration>>), and its sub-agents receive the Micronaut model, memory, retrieval and tool configuration of their agent id like any other agent. `responseStrategy` selects whether the supervisor answers with the last response of a sub-agent (`LAST`, the default), with the summary written by the planner (`SUMMARY`) or with the better of both (`SCORED`).

[[agenticSuppliers]]
=== Supplier methods

LangChain4j agents can declare static supplier methods, such as `@ChatModelSupplier`, `@ToolsSupplier`, `@ToolProviderSupplier`, `@ContentRetrieverSupplier`, `@ChatMemoryProviderSupplier`, `@ParallelExecutor` or `@McpClientSupplier`. With Micronaut, the parameters of these methods are beans: annotate a parameter with `@Named` to select a bean by name.

NOTE: LangChain4j calls a `@ChatModelSupplier` or `@StreamingChatModelSupplier` method that has parameters for each invocation of the agent within a workflow: a standalone typed agent ignores it.

==== MCP client agents

An MCP client agent calls a tool of an MCP server as a step of a workflow. Add the LangChain4j agentic MCP dependency, together with an MCP client, for example the one of https://micronaut-projects.github.io/micronaut-mcp/latest/guide/[Micronaut MCP]:

dependency:langchain4j-agentic-mcp[groupId=dev.langchain4j]

dependency:micronaut-mcp-client-langchain4j[groupId=io.micronaut.mcp]

The `@McpClientSupplier` method receives the `McpClient` bean of the server:

snippet::example.micronaut.agentic.WorldClockAgent[source=main]

<1> The tool of the MCP server to call. The arguments of the tool are the parameters of the method, read from the agentic scope.
<2> The Micronaut MCP client bean named `time-server`, configured under `micronaut.mcp.client.http.time-server` (see <<tools, Tools>> for an MCP client configuration).

NOTE: In Python, a class with a static function compiles to a Java interface only when it is an introduction type, so the MCP client agent above is an `@AgenticService` too.

==== A2A client agents

LangChain4j's `@A2AClientAgent` invokes a remote agent with the https://a2a-protocol.org[Agent2Agent (A2A)] protocol. It requires the `dev.langchain4j:langchain4j-agentic-a2a` dependency, and the URL of the remote agent server is set with the `a2aServerUrl` attribute or returned by a static `@A2AServerUrlSupplier` method without parameters. A static `@A2AClientCustomizer` method can customize the A2A client.
