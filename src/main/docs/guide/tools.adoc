The tools are not discovered by LangChain4j scanning the tool class: Micronaut builds the `ToolSpecification` of each `@Tool` method from its compile-time metadata (the method and parameter names, `@Tool`, `@P`, `@ToolMemoryId`) and invokes the method through its Micronaut `ExecutableMethod`. Tool classes therefore need no reflection, neither in a GraalVM native image nor for classes written in Python. The tools of a service are also available programmatically, as LangChain4j `AiServiceTool` instances, from api:io.micronaut.langchain4j.tools.ToolRegistry#getAiServiceTools(java.util.Set)[].

NOTE: LangChain4j's `@CompensateFor` compensating actions are not supported, since LangChain4j only registers them for the tools it discovers reflectively.

=== Tool Providers

Tools can also be provided dynamically by a LangChain4j https://docs.langchain4j.dev/tutorials/tools#dynamic-tool-provisioning[ToolProvider] bean, for example the tool provider of the https://micronaut-projects.github.io/micronaut-mcp/latest/guide/#clientLangchain4j[Micronaut MCP LangChain4j client], which provides the tools of the configured MCP servers.

snippet::example.micronaut.aiservice.tools.WeatherToolProvider[source="main"]

<1> The tool provider is a bean qualified with a name.
<2> It returns the specifications of the tools and the executors that invoke them.

Name the tool providers of an AI service with the `toolProviders` member of `@AiService`:

snippet::example.micronaut.aiservice.tools.WeatherAssistant[source="main"]

<1> The AI service uses the tools of the `ToolProvider` bean named `weather`.

An AI service uses the following tool providers:

* The `ToolProvider` beans named by the `toolProviders` member of `@AiService`. Set the member to an empty array to use no tool provider.
* Otherwise, the `ToolProvider` bean qualified with the name of the service, given by the `named` member of `@AiService`.
* Otherwise, the default `ToolProvider` bean: the only `ToolProvider` bean without a qualifier (or annotated with `@Primary`). Tool providers qualified with a name are only used by the services that select them, and when there are several unqualified tool providers none of them is used implicitly, so that tools are never exposed to a service by accident.

The following LangChain4j beans are also applied to AI services, preferring a bean qualified with the name of the service over the default bean:

* `ToolExecutionErrorHandler` - converts an exception thrown by a tool into the result sent to the model.
* `ToolArgumentsErrorHandler` - handles arguments the model sent that cannot be parsed.
* `ToolSearchStrategy` - selects the tools sent to the model when there are many tools.

=== Tool Calling Configuration

The tool calling loop of the AI services can be configured under `langchain4j.ai-services`. The `default` entry applies to every AI service, an entry with the name of a service replaces it for that service:

.Example Configuration
[configuration]
----
langchain4j:
  ai-services:
    default:
      max-tool-calling-round-trips: 10
    weather:
      execute-tools-concurrently: true
      tool-executor: virtual
----

=== MCP Tools

The tools of https://modelcontextprotocol.io[Model Context Protocol] (MCP) servers can be provided to AI services with the https://micronaut-projects.github.io/micronaut-mcp/latest/guide/#clientLangchain4j[Micronaut MCP LangChain4j client]:

dependency:micronaut-mcp-client-langchain4j[groupId=io.micronaut.mcp]

The client creates a LangChain4j `McpClient` bean for each configured MCP server, named after its configuration, and a `ToolProvider` bean that provides the tools of all of them.

.Example Configuration
[configuration]
----
micronaut:
  mcp:
    client:
      http:
        github:
          url: https://example.com/mcp
----

This `ToolProvider` is unqualified, so when it is the only unqualified one it is the default tool provider of the AI services that do not select tool providers (see the previous section): they receive the tools of every configured MCP server. To restrict a service to some MCP servers, name their clients with the `mcpClients` member of `@AiService`:

snippet::example.micronaut.aiservice.mcp.GitHubAssistant[source="main"]

<1> The AI service only receives the tools of the MCP server configured under `micronaut.mcp.client.http.github`.

When `mcpClients` is set, no `ToolProvider` bean is applied implicitly. Combine it with `toolProviders` to add other tool providers. The `mcpClients` member requires `dev.langchain4j:langchain4j-mcp` on the classpath, which the Micronaut MCP LangChain4j client provides.

To expose the tools of a Micronaut application as an MCP server, see the https://micronaut-projects.github.io/micronaut-mcp/latest/guide/#server[Micronaut MCP server documentation].
